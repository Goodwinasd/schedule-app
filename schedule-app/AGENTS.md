## 1. Что это за проект (минимум контекста)

- Размер: `routes.py` — 3603 строки (~84 правила в одном Blueprint), 16 JS-модулей
  (~3.6k строк), `style.css` — 3048 строк, `templates/index.html` — 369 строк.
- Платформа разработки: **Windows** (`.bat`-скрипты, пути `C:\...`). Шелл — PowerShell/cmd, не bash.
- Тесты: **357** (`350` в `tests/` + `7` e2e в `tests/e2e/`), фреймворк — pytest, e2e — Playwright/Chromium.
- Миграции: Alembic, **14 ревизий, линейная цепочка, head = `a9b8c7d6e5f4`** (смены групп, типы аудиторий, требуемый тип аудитории у предметов).
- Git: репозиторий инициализирован в корне воркспейса (`Default Project`),
  релизная ветка — `release/v1.0` (все фича-ветки влиты; `origin/main` пока не тронут).

## 2. Жёсткие запреты (нарушение = стоп, доложить пользователю)

1. **Не трогать `.env`.** Ни читать в вывод, ни редактировать, ни коммитить.
   Если задача требует изменения `.env` — остановиться и попросить пользователя.
2. **Не трогать `data/` и `backups/`.** Это боевая БД и её бэкапы.
   - Никогда не вызывать `POST /api/admin/backup/restore` против `data/schedule.db`.
   - Тесты restore — только против временной копии во временной папке.
3. **Не выполнять разрушительные git-команды:**
   `git reset --hard`, `git clean -fd`, `git push --force`, `git checkout .`,
   `git branch -D` для чужих веток, `git rebase` без явного разрешения.
4. **Не коммитить самовольно.** Порядок: правка → `git diff` → тесты →
   показать пользователю → дождаться «ок» → коммит.
5. **Не запускать `restart.bat`** — там `taskkill /f /im python.exe`, он убивает
   все Python-процессы на машине, включая чужие.
6. **Не менять схему БД** (миграции, `ensure_*`, `CREATE TABLE`) без отдельной
   задачи и без прогона `alembic upgrade head` на пустой БД.
7. **Не рефакторить «по пути».** Чинишь CSRF-токен — не разбивай `routes.py`
   на blueprint'ы. Рефакторинг — только отдельная задача.
8. **Не устанавливать зависимости** и не менять `requirements.txt` без разрешения.

## 3. Экономия токенов и контекста (Token Economy)

Чтобы не сжигать контекст впустую и не терять фокус:
1. **Никогда не читай файлы целиком**, если они больше 200 строк (`routes.py`, `style.css`). Используй `grep -n "def function_name"` или `sed -n '100,150p' file.py`, чтобы прочитать только нужный фрагмент.
2. **Показывай только `git diff`**. Никогда не вставляй в ответ полные файлы, если пользователь не попросил об этом явно.
3. **Батчинг:** Объединяй независимые команды Shell в одну строку (например, `git status && git diff --stat`).
4. **Логи тестов:** Всегда запускай `pytest -q --tb=short`. Если тест упал, читай только последние 20 строк вывода.
5. **Краткость:** Отвечай на русском языке, кратко и по делу. Не пиши длинных вступлений и извинений. Сначала код/дифф, потом краткое пояснение.

## 5. Генератор расписания

`generator.py` работает в две фазы:

1. **Фаза 1 (жадный черновик):** раскладка по реальным нормам — будни 3–4 пары с 1-й пары,
   суббота 2 (максимум 3), блоки сплошные без окон. Дневные лимиты: 4 пары (будни), 3 (суббота).
   Пары не выбрасываются при коллизиях: top-up добирает их в свободные слоты других дней.
2. **Фаза 2 (имитация отжига, `_optimize_schedule`):** перестановка периодов, чтобы убрать окна.
   Штрафы: окно группы **100 + 100·gap**, пустая пара в начале дня **100**, окно преподавателя
   10 + 6·gap, перегруз 5/пара. 4 пары подряд — норма (штраф 0). Таймаут 2.5 с, детерминизм по seed.
   В БД пишется только `period` и только в пределах одной даты (`same_date_only=True`) —
   иначе свап дат даёт дубли периодов.

Ограничение: генерация идёт по одной группе; потоки (2–3 группы в одной аудитории с одним
преподавателем) не поддерживаются — это требует схемы `lesson ↔ groups` (many-to-many).

### Правила реального расписания (с 28.10.2026)

- `groups_list.shift`: 1 — 1-я смена (с 8:30, пары 1–4), 2 — 2-я смена (с 13:30, пары 3–7,
  ожидаемый старт — 4-я пара). `NULL` — прежняя логика (старт с 1-й).
- `classrooms_list.room_type`: `normal`/`NULL` — обычная, `gym` — спортзал, `computer` — компьютерный
  класс, `court` — зал суда.
- `subjects.required_room_type`: предмет ставится только в аудиторию этого типа
  (физкультура → `gym`, информатика → `computer`); без значения — любая свободная обычная.
- Максимум для генератора — **7-я пара** (`GENERATOR_MAX_PERIOD`), 8-ю не ставим.
- Тесты на правила: `tests/test_generator_real_rules.py`.
