# AGENTS.md — правила работы агента с проектом `schedule-app`

Этот файл читается агентом перед каждой задачей. Если правило противоречит
пользовательскому запросу — **побеждает правило**, агент обязан спросить.

---

## 1. Что это за проект (минимум контекста)

- Flask + SQLite (WAL) + Alembic, ванильный JS SPA (ES-модули, без сборщика),
  экспорт XLSX/DOCX/PDF через `openpyxl` / `python-docx` / **`reportlab`**.
- Однопользовательское приложение: один администратор, вход по паролю из `.env`.
- Размер: `routes.py` — 3603 строки (~84 правила в одном Blueprint), 16 JS-модулей
  (~3.6k строк), `style.css` — 3048 строк, `templates/index.html` — 369 строк.
- Платформа разработки: **Windows** (`.bat`-скрипты, пути `C:\...`). Шелл — PowerShell/cmd, не bash.
- Тесты: **309** (`304` в `tests/` + `5` e2e в `tests/e2e/`), фреймворк — pytest, e2e — Playwright/Chromium.
- Миграции: Alembic, **13 ревизий, линейная цепочка, head = `f7g8h9i0j1k2`**.
- Git: репозиторий инициализирован в корне воркспейса (`Default Project`),
  рабочая ветка UI-рефакторинга — `ui/modernization`.

## 2. Жёсткие запреты (нарушение = стоп, доложить пользователю)

1. **Не трогать `.env`.** Ни читать в вывод, ни редактировать, ни коммитить.
   Если задача требует изменения `.env` — остановиться и попросить пользователя.
2. **Не трогать `data/` и `backups/`.** Это боевая БД и её бэкапы.
   - Никогда не вызывать `POST /api/admin/backup/restore` против `data/schedule.db`.
   - Тесты restore — только против временной копии во временной папке.
3. **Не выполнять разрушительные git-команды:**
   `git reset --hard`, `git clean -fd`, `git push --force`, `git checkout .`,
   `git branch -D` для чужих веток, `git rebase` без явного разрешения.
4. **Не коммитить самовольно.** Порядок: правка → `git diff` → тесты →
   показать пользователю → дождаться «ок» → коммит.
5. **Не запускать `restart.bat`** — там `taskkill /f /im python.exe`, он убивает
   все Python-процессы на машине, включая чужие.
6. **Не менять схему БД** (миграции, `ensure_*`, `CREATE TABLE`) без отдельной
   задачи и без прогона `alembic upgrade head` на пустой БД.
7. **Не рефакторить «по пути».** Чинишь CSRF-токен — не разбивай `routes.py`
   на blueprint'ы. Рефакторинг — только отдельная задача.
8. **Не устанавливать зависимости** и не менять `requirements.txt` без разрешения.

## 3. Рабочий процесс (одна задача = одна ветка = один коммит)

```bat
:: 1. старт задачи
git status
git checkout main
git checkout -b fix/<кратко-о-задаче>

:: 2. работа (агент правит, пользователь смотрит diff)

:: 3. проверка
git diff
pytest tests/ -k <релевантное> -q

:: 4. после «ок» от пользователя
git add -A
git commit -m "fix: <что и зачем>"

:: 5. работает — влить
git checkout main
git merge --no-ff fix/<кратко-о-задаче>
git tag working-YYYY-MM-DD

:: 6. не работает — выбросить
git checkout main
git branch -D fix/<кратко-о-задаче>
```

Полная проверка перед коммитом: `python -m pytest tests/ -q --ignore=tests/e2e`,
затем `python -m pytest tests/e2e -q` (нужен установленный Chromium Playwright).

## 4. Дизайн-система (UI)

Стили живут в `static/css/style.css`. С июля 2026 в файле действует токен-система;
все новые и изменяемые правила **обязаны** её использовать.

1. **Источник значений — `:root`** (палитра, типографика, отступы, радиусы, тени,
   высоты контролов, фокус). Тёмная тема — блок `[data-theme="dark"]`.
2. **Старые имена — алиасы** на новые токены (`--bg: var(--color-bg)` и т.п.).
   Не удалять их, пока весь файл не переведён на новые имена.
3. **Никаких литеральных цветов** в новых правилах: только `var(--color-*)`,
   `var(--accent-500/600/700)`, `var(--warning-*)` и т.п.
4. **`!important` — только** в `@media print`, `prefers-reduced-motion` и
   вынужденных мобильных переопределениях. В обычных правилах — запрещён;
   специфичность добирается селектором (пример: `.schedule-table tbody td.day-cell.drag-hover`).
5. **Инлайн-стили в разметке запрещены**, кроме `style="display:none"` на
   контейнерах: видимостью управляет JS через `style.display = ''`, поэтому
   класс `.is-hidden` там не сработает. Остальное — утилиты из конца `style.css`
   (`.mw-*`, `.spacer-*`, `.checkbox-row`, `.hint-text`, `.divider`, `.panel-pad`, `.text-sm`).
6. **Шаг сетки — 4px:** `--space-1..12`. Высоты контролов: `--control-h-sm 32`,
   `--control-h 36`, `--control-h-lg 40`. Радиусы: `--radius-xs 6`, `-md 12`, `-lg 16`, `-xl 20`.
7. **Не менять разметку внутри элементов, к которым привязан JS**: селекторы
   `#id`, `.schedule-table tbody td.day-cell`, `.lesson-content`, `.time-cell`
   используются в `schedule.js` (drag&drop, клики, `lessonsMap`).
8. **Проверка UI — в браузере, а не на глаз:** вычисленные стили через Playwright
   (`getComputedStyle`) и скриншоты в `docs/ui/`. Пиксельные артефакты превью
   проверять сэмплированием пикселей PNG, а не глазами.
