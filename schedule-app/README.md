# schedule-app

Расписание занятий колледжа/техникума: Flask + SQLite, SPA на ванильном JS (без сборщика),
экспорт в XLSX/DOCX/PDF. Однопользовательское приложение: один администратор входит по паролю.

## Возможности

- справочники: группы (курс, специальность, заочка), преподаватели, предметы, аудитории, специальности;
- учебные планы (`curriculum`) и прогресс по семестру;
- недельное расписание (Пн–Сб, пары 1–8, подгруппы) с проверкой конфликтов;
- автогенератор: приоритет отстающим предметам, лимиты 4/3 пары, замены преподавателей, зеркалирование составных потоков;
  раскладка по реальным нормам (будни 3–4 пары с 1-й, суббота 2) + имитация отжига без окон (2.5 с, детерминизм по seed);
- черновики и публикация недели, корзина (soft-delete), история изменений;
- экспорт XLSX/DOCX/PDF по группе/преподавателю/аудитории + сводный Excel;
- импорт справочников из Excel, бэкапы БД, диагностика (`PRAGMA integrity_check`), схема звонков.

## Требования

- **Python 3.13** (проверено на 3.13.14), pip;
- Windows (основная платформа) или Linux;
- для e2e-тестов — Playwright + Chromium.

## Установка

```bat
cd schedule-app
python -m pip install -r requirements.txt
python -m pip install -r requirements-dev.txt   :: только для тестов
```

## Настройка `.env`

Файл `.env` лежит рядом с `app.py` и **никогда не коммитится** (см. `.gitignore`).
Шаблон — `.env.example`.

| Переменная | Обязательна | Описание |
|---|---|---|
| `SCHEDULE_PASSWORD` | **да** | пароль администратора: минимум 8 символов, цифра и спецсимвол `!@#$%^&*()_+-=`. Без него приложение не стартует |
| `SCHEDULE_SECRET_KEY` | нет | ключ подписи сессий. Если пуст — сгенерируется и допишется в `.env` при первом запуске |
| `FLASK_DEBUG` | нет | `1/true/yes` включает debug. **На рабочем сервере оставлять пустым** |
| `FLASK_HOST` / `FLASK_PORT` | нет | по умолчанию `127.0.0.1:5000` |
| `SCHEDULE_DATA_DIR` / `SCHEDULE_BACKUPS_DIR` | нет | переопределяют каталоги БД и бэкапов |

Пароль проверяется на старте (`config.py`): «слабый» пароль — приложение не поднимется.
Хеш считается заново при каждом запуске, поэтому смена пароля = правка `.env` + перезапуск.

## Запуск

```bat
cd schedule-app
python app.py
```

Открыть http://127.0.0.1:5000. Режим `python app.py` дополнительно:
делает бэкап, применяет миграции, сидит стартовые специальности,
чистит корзину старше 30 дней и запускает планировщик бэкапов (каждые 6 часов).

Альтернатива без этих побочных эффектов (полезно при отладке на боевой БД):

```bat
python -m flask --app app run --port 5000
```

Вспомогательные скрипты: `run.bat` (запуск), `start.bat`, `restart.bat`.
**`restart.bat` убивает все процессы `python.exe` на машине** — не использовать без необходимости.

## Docker (production)

> ⚠️ **Перед запуском в production обязательно смените `SCHEDULE_PASSWORD` и `SCHEDULE_SECRET_KEY` в `.env`.** Дефолтные/засвеченные значения недопустимы: ключ подписи сессий позволяет подделать вход администратора.

```bash
cp .env.example .env            # заполнить SCHEDULE_PASSWORD и SCHEDULE_SECRET_KEY
docker compose up -d --build    # web + backup
docker compose ps               # статус, healthcheck
docker compose logs -f web
docker compose down
```

- образ `python:3.13-slim`, пользователь `appuser` (non-root), WSGI — `waitress` (один процесс:
  кэш справочников и планировщик не конфликтуют);
- `fonts-dejavu-core` в образе — кириллица в PDF;
- `./data` и `./backups` — volumes, переживают пересоздание контейнера;
- миграции и seed выполняются при старте (`docker/entrypoint.sh`);
- бэкапы — отдельный сервис `backup` (вне веб-процесса), каждые 6 часов;
- healthcheck: `GET /api/health` → `{"status":"ok","db":"ok"}`;
- наружу порт 5000; в проде — за reverse-proxy (nginx/Caddy) с HTTPS.

## Тесты

```bat
python -m pytest tests/ -q --ignore=tests/e2e     :: 343 теста
python -m pytest tests/e2e -q                     :: 5 e2e (Playwright)

:: подготовка e2e (один раз)
python -m pip install pytest-playwright
python -m playwright install chromium
```

Тесты работают на временной БД: `conftest.py` поднимает temp-файл, применяет Alembic
и отказывается чистить каталог, если путь не во временной папке.

## Данные и бэкапы

| Путь | Что это |
|---|---|
| `data/schedule.db` | **боевая БД** (SQLite, WAL). Не редактировать вручную |
| `backups/db_backup_*.sqlite` | копии при старте и восстановлении, хранится 10 последних |
| `backups/schedule_backup_*.db` | ежедневные копии планировщика, удаляются по `backup_retention_days` |

- Скачать копию: `GET /api/admin/backup/download` (админ).
- Восстановить: `POST /api/admin/backup/restore` с файлом `.db`/`.sqlite` — **перезаписывает боевую БД**,
  перед этим делает страховочную копию.
- В репозиторий `data/` и `backups/` не попадают.

## Миграции

```bat
alembic upgrade head        :: 13 ревизий, линейная цепочка, head = f7g8h9i0j1k2
alembic current
```

Важно: таблица `curriculum` создаётся **кодом** (`db.ensure_curriculum_table()`), а не миграцией,
поэтому `alembic upgrade head` на пустой БД даёт неполную схему — приложение дополняет её на старте.

## Стиль кода и UI

- Python: PEP 8, русские комментарии «почему», а не «что».
- UI: только токены из `:root` (`--color-*`, `--accent-*`, `--space-*`, `--radius-*`, `--shadow-*`),
  без литеральных цветов и без `!important` вне `@media print`/`prefers-reduced-motion`.
  Инлайн-стили запрещены, кроме `style="display:none"` (видимостью управляет JS).
- Подробности и запреты — в `AGENTS.md`, раздел «Дизайн-система».

## Безопасность

- один администратор, пароль в `.env`; ролей и аудита «кто изменил» пока нет;
- всегда работайте через HTTPS на внешнем прокси: приложение само TLS не терминирует;
- ротируйте `SCHEDULE_SECRET_KEY` и пароль, если они где-то засветились
  (ротация ключа разлогинивает все сессии);
- `python app.py` — это dev-сервер Werkzeug. Для нескольких пользователей нужен
  WSGI-сервер (waitress/gunicorn) и reverse proxy, см. `docs/200-users-plan.md`.
